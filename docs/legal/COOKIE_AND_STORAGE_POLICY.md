## 1. Zero-Cookie, Zero-Storage Application Architecture
The standalone interactive dashboard (`dashboard.html`) generated by `github-repo-kb-skill` is engineered to operate without browser tracking or client-side persistence:

| Storage / Tracking Mechanism | Used by `dashboard.html`? | Details |
|---|---|---|
| HTTP / JavaScript Cookies (`document.cookie`) | **No** | Zero first-party or third-party cookies set by the dashboard. |
| `localStorage` | **No** | Theme selection (`dark` / `light`) and filter states exist only in volatile in-memory DOM state and reset on page reload. |
| `sessionStorage` | **No** | Not accessed. |
| `IndexedDB` / Cache Storage / Service Workers | **No** | Not accessed. |
| Third-Party Scripts, Pixels, Web Fonts, or Analytics | **No** | D3.js v7.9.0 is vendored inline; system UI fonts are used; CSP enforces `default-src 'none'` and `font-src 'none'`. |
| Automatic External Requests on Page Load | **No** | Zero outbound requests on initial load. |

## 2. Consent Banner Assessment (ePrivacy Directive / PECR)
Because `dashboard.html` sets **zero cookies**, writes **zero client storage**, and makes **zero external network requests** unless the user explicitly clicks **Scan Address** or chooses a live GitHub preset, **no cookie consent banner is required** for the standalone dashboard itself.

## 3. User-Initiated External Requests
When you explicitly trigger a live scan in the dashboard header (**Scan Address** or selecting a live GitHub preset), your browser sends an anonymous (`credentials: 'omit'`, `referrerPolicy: 'no-referrer'`) HTTPS `GET` request directly to `https://api.github.com` to fetch public repository metadata.
